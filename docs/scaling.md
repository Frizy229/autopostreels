# Масштабирование: хранилище, лимиты, команда

## 1. Где хранятся видео

С виджета **4.6.0** видео не попадают в git. Виджет загружает их в релиз
[`media`](https://github.com/Frizy229/autopostreels/releases/tag/media) (бесплатно, до 2 ГБ на файл), а в папку очереди
кладёт маленькую заглушку `short-1.mp4.remote.json` (рядом, как раньше, `.txt` и обложка).

- Автопостер скачивает ролик перед публикацией, один раз на все аккаунты.
- Через **2 дня** после того, как папка переехала в `posted…/`, видео удаляется из релиза. В заглушке появляется
  `"deleted": "дата"`. Срок задаётся в `config.json` → `media_keep_days`.
- Не удалять конкретный ролик: в его заглушке поставить `"keep": true` (повторы лучших роликов делают это сами).
- Статистика (просмотры, лайки, охват) не пропадает: она приходит из Instagram по id публикации, файл не нужен.
- Вернуть старый способ (видео в git): `config.json` → `"media_storage": "git"`.

Старые видео в истории репозитория (≈1,8 ГБ) больше не прибавляются и публикацию не тормозят: Actions скачивает
только текущую версию. Переписывать историю не нужно.

Нужно, чтобы у токена виджета было право **Contents: Read and write** (уже есть): им же создаются ассеты релиза.

## 2. Лимиты при 10+ аккаунтах по 10 роликов

| Что | Лимит | Что у нас |
|---|---|---|
| Instagram API | 50 публикаций за 24 ч на аккаунт (в некоторых аккаунтах 100) | 10 в день — с запасом. Автопостер перед публикацией спрашивает остаток (`content_publishing_limit`); если 0, аккаунт ждёт следующего запуска, другие публикуют |
| Запросы к API | ~200 × число пользователей приложения в час | Одна публикация ≈ 5–10 запросов, хватает |
| GitHub Actions | бесплатно для публичного репозитория; запуск до 6 ч, у нас таймаут 30 мин | Аккаунты публикуют **одновременно** (`parallel_accounts`, по 4), лимит считается **на аккаунт** (`max_posts_per_account_run`) |
| Релиз GitHub | файл до 2 ГБ, общий объём не ограничен явно | Видео живут 2 дня: при 100 роликах в день ≈ 200–300 файлов |

Рекомендации, чтобы аккаунты не банили: не больше 10–15 рилсов в день на аккаунт, разные подписи (A/B подписи помогают),
не ставить одинаковое время на всех аккаунтах (окно группы распределяет ролики само), новым аккаунтам первую неделю
2–3 ролика в день.

## 3. Команда: каждый участник независим

Цель: если заблокируют твой аккаунт Facebook или приложение Meta «Auto», участники продолжают работать.

Что общего сейчас и почему это риск:
- **приложение Meta «Auto»** — твоё. Его блок = все токены через него перестают работать;
- **Страницы Facebook** привязаны к твоему профилю. Блок профиля = потеря доступа к Страницам и Instagram-аккаунтам на них;
- **репозиторий** твой: участник без доступа не может ничего поменять.

### Правильная схема (рекомендую)

У каждого участника **всё своё**:

1. **Свой GitHub и своя копия репозитория.** Участник: [зарегистрироваться на GitHub](https://github.com/signup) →
   открыть [репозиторий](https://github.com/Frizy229/autopostreels) → **Use this template / Fork** (или ты даёшь
   копию через виджет: «Копия для друга», см. [accounts-setup.md](accounts-setup.md)).
   В копии: Settings → Actions → включить; удалить из `config.json` твои аккаунты.
2. **Свой профиль Facebook** (настоящий, с пройденной проверкой личности) и **свои Страницы** под свои Instagram.
3. **Своё приложение Meta**: [developers.facebook.com/apps](https://developers.facebook.com/apps/) → «Создать приложение»
   → тип «Другое» → «Бизнес» → продукты «Вход через Facebook» и «Instagram» (по [accounts-setup.md](accounts-setup.md#один-раз-подготовка)).
   Адрес возврата — страница его копии: `https://<его-ник>.github.io/autopostreels/` (включить GitHub Pages в копии)
   или твой `https://frizy229.github.io/autopostreels/` — страница только передаёт код в виджет, ничего не хранит.
4. **Свой виджет** с токеном GitHub на **его** репозиторий. Аккаунты он подключает сам через «+ аккаунт».
5. Свой будильник [cron-job.org](https://cron-job.org/) на его репозиторий (как у тебя).

Твой блок никак его не затронет, и наоборот. Минус: обновления программы участник забирает сам
(GitHub → его копия → **Sync fork**).

### Промежуточный вариант (если участники пока работают в твоём репозитории)

- Перенеси приложение «Auto» в **Business-портфолио** ([business.facebook.com](https://business.facebook.com/settings/)
  → Аккаунты → Приложения → Добавить) и добавь **второго администратора** (доверенный человек) в портфолио и в приложение
  (developers.facebook.com → приложение → Роли приложения → Администраторы).
- Страницы Facebook тоже добавь в портфолио и дай второму админу полный доступ: при блоке твоего профиля он
  переподключит аккаунты через свой вход.
- Используй для основных аккаунтов **токен системного пользователя** портфолио (как `IG_TOKEN` у dayzerorules): он
  не привязан к личному профилю и не истекает.
- Участникам дай доступ к репозиторию (Settings → Collaborators) и заведи каждому свою **группу** ([groups.md](groups.md)).
